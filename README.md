# TinyKernel

**Laboratório experimental de causalidade mínima**

TinyKernel investiga uma pergunta deliberadamente simples e radical:

> Qual é a menor estrutura causal necessária para que um fenômeno continue sendo aquilo que é?

O projeto não parte da premissa de que exista um Kernel único, universal ou
previamente identificável.

Seu objeto inicial de investigação é a **minimalidade causal**.

A estratégia experimental combina dois movimentos:

    construir <-> remover

O objetivo é investigar experimentalmente distinções como:

- suficiência;
- necessidade;
- irredutibilidade;
- causalidade;
- significado;
- observabilidade;
- realizações alternativas.

TinyKernel pertence à linhagem experimental iniciada por TinyLogicLM e
TinyLogicVision, mas constitui um laboratório independente.

Ele não existe para confirmar antecipadamente uma teoria de Kernel.

Existe para tornar materialmente possível descobrir quais estruturas são
necessárias para preservar um fenômeno — e também para descobrir onde nossas
próprias hipóteses estão erradas.

## Princípio fundador

> Encontrar um Kernel não consiste em escolher antecipadamente seus componentes,
> mas em remover abstrações até que uma remoção adicional destrua causalidade,
> significado ou capacidade.

O objeto científico inicial não é "Kernel" como entidade dada.

É a **minimalidade causal**.

Um Kernel, se essa categoria sobreviver à investigação, deverá emergir como
resultado experimental limitado por fenômeno, contexto, witnesses e intervenções.

## Estado do projeto

TinyKernel inicia deliberadamente sem implementação substantiva.

A pergunta deve preceder a máquina.

O primeiro passo experimental será TK-0000: construir e verificar o aparato
mínimo capaz de executar:

    baseline
    -> witness
    -> intervention
    -> witness
    -> classification

Somente depois desse aparato ser demonstrado deverá começar a investigação
substantiva da minimalidade causal.

## Princípio operacional

**READY != COMPLETE**

Sempre pronto significa que o estado publicado deve ser executável, verificável
e reconstruível.

Sempre incompleto significa que nenhuma realização, ontologia ou Kernel deve ser
universalizado além da evidência que o sustenta.

**Sempre pronto. Sempre incompleto.**
